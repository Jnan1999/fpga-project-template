# 00-02 需求规格说明书（SRS / Functional Specification）

> 本文档回答“系统**必须做什么**”，不回答“怎么实现”。每条需求必须：唯一编号、可验证、无歧义、带验收方法。它是设计、验证、验收的共同依据，冻结后变更必须走变更流程。

## 1. 引言
1.1 目的
1.2 适用范围与读者（设计、验证、软件、测试、客户）
1.3 术语与缩写（如 FBG、LVDS、AXIS、DMA、CDC……）
1.4 参考文档（数据手册、协议标准、上位机接口协议）

## 2. 系统总体描述
- 2.1 系统组成与运行环境（板卡、传感器、上位机、连接拓扑）
- 2.2 用户使用场景（典型工作流：上电 → 连接 → 下命令 → 采集 → 出结果）
- 2.3 约束条件：器件型号、工具链版本、成本、功耗、开发周期

## 5. 外部接口需求（概要，详细见 ICD）
- 5.1 物理接口：ADC LVDS 引脚、以太网、UART、时钟、触发
- 5.2 通信协议：UDP 帧格式、命令字表、波特率/网口参数（IP/端口/MAC）
- 5.3 PS↔PL 接口：AXI-Lite 寄存器、AXI-Stream/DMA 数据通道、中断
- 5.4 电气与电平：电平标准、差分、时钟抖动、IO 标准

## 6. 异常与可靠性需求
- 异常清单：链路断连、丢包、FIFO 溢出、ADC 失锁、时钟失锁、非法命令、复位
- 每条异常的检测方式、系统行为（报警码/恢复策略）、恢复时间要求
- 上电自检要求；长稳、温漂（如 ADC 相位漂移）适应性要求

## 7. 可测试性/可维护性需求
- 关键状态/计数器必须可通过寄存器读取（与 DFT 包装层对应）
- 支持测试码注入、故障注入接口（仿真与板级复用）
- 软件应可复现构建；版本号、构建信息可查询

## 8. 需求追溯
- 所有 FR/PR 必须在《需求跟踪矩阵 RTM》中登记，映射到设计章节、验证用例、测试结果。
