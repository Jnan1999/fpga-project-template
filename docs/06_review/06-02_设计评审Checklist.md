# 设计评审 Checklist（评审通用检查单）

> 评审时逐项打勾，任何“必过项”不满足不得进入下一阶段。括号内为该检查项对应的文档/位置。

## A. 需求与架构
- [ ] 每条需求有唯一编号、可测量、有验收方法（SRS/RTM）
- [ ] 需求覆盖率 100%，每条需求都有设计与验证落点（RTM）
- [ ] 模块划分合理，顶层只做互连，模块间走标准握手（HLD）
- [ ] PS/PL 职责划分有明确依据，关键权衡有记录（HLD §10）
- [ ] 数据帧格式、命令字、缓冲与零拷贝方案完整（ICD/软件架构）

## B. 接口与寄存器
- [ ] 所有外部接口有时序参数、电平、引脚定义（ICD）
- [ ] 寄存器地址/权限/复位值/位域/错误码完整且与驱动一致（寄存器规格）
- [ ] 非法访问、保留位、锁存与清零行为有定义
- [ ] 接口变更有三方会签记录

## C. 时钟/复位/CDC
- [ ] 时钟树完整，来源/频率/关系明确，无逻辑门控时钟
- [ ] CDC 清单逐条列出，同步方式正确，约束对应
- [ ] 复位树为异步复位同步释放，复位顺序明确，所有寄存器可复位

## D. 模块详细设计
- [ ] 每个模块有 LLD，接口、微架构、FSM、存储单元完整
- [ ] 位宽/定点格式/截位饱和规则明确，无隐式扩展
- [ ] FIFO 深度有计算依据，空满/prog_full 保护齐全
- [ ] 状态机有默认/复位分支，无死锁、无 latch
- [ ] 关键路径与资源估算有结论
- [ ] 功能核心与 DFT 包装分离，核心 RTL 无调试代码

## E. 验证
- [ ] 验证计划与 LLD 并行，验证点覆盖需求和边界
- [ ] 有 Golden Model 与逐拍/逐帧比对、SVA 断言、计数器
- [ ] 边界三点法、反压、复位、组合场景在测试矩阵中
- [ ] 覆盖率目标准确，未覆盖项有闭环记录
- [ ] 随机用例固定种子、可复现

## F. 实现与时序
- [ ] 所有时钟/IO 已约束，无未约束路径
- [ ] 时序例外逐条有理由和评审
- [ ] WNS/WHS 收敛且有裕量，资源 <80%
- [ ] report_cdc 无未处理 critical

## G. 板级与发布
- [ ] Bring-up 有顺序、有判据、有失败排查路径
- [ ] 板级用例覆盖 RTM，数据正确性可自动比对
- [ ] 缺陷台账完整，关键问题根因清晰
- [ ] 版本可复现构建，Release Notes、回退版本齐全
