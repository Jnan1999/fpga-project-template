## 1. 验证目标与范围
- 1.1 验证目标（功能正确、协议合规、边界鲁棒、精度达标、量化覆盖率）
- 1.2 验证范围（In Scope）：列出本模块/本系统所有功能
- 1.3 不验证范围（Out of Scope）：时序收敛、电气特性、IP 黑盒内部（引用 IP 厂商保证）
- 1.4 验证层次：模块级（SV 分层平台）→ 系统级（PL 全链路）→ 板级（见 05 文档）

## 2. 验证策略
- 分层验证：模块级由各自 Testbench 负责；PS-PL 接口、DMA、帧协议由系统级负责
- 检查机制：SVA 断言（协议/时序）+ Scoreboard（对 Golden Model 逐拍/逐帧比对）+ 计数器（数据连续性）
- 激励方式：定向用例（正常/边界）+ 约束随机（反压、位置、幅值、噪声）+ 故障注入
- 参照模型：host/golden_model（Python 定点模型），同一输入同时喂 RTL 与模型
- 复用：接口断言同时用于 DFT 硬件检查；测试向量同时用于板级注入

## 3. 验证环境
- 工具：Vivado xsim / （其他）；SystemVerilog 支持
- 平台分层（5 层）：interface → driver/monitor → generator → scoreboard/coverage → test
- 目录：hw/verif/{tb,sv,stimulus,ref_model,scripts,report}（本模板实际路径，旧称 hw/sim 已废弃）
- 通用脚本：hw/verif/scripts/run_sim.tcl（编译→仿真→覆盖率→报告）

## 5. 测试用例与回归矩阵（摘要，完整版见 03-02）
- 冒烟集（Smoke）：__ 个，__ 分钟，提交必跑
- 基础集（Regression）：__ 个，每日/每次改动跑
- 全量集（Full）：含随机种子集、压力、长稳，版本节点跑
- 随机验证：每个随机用例固定种子集合 + 每周扩展种子；失败用例必须保留可复现种子

## 6. 覆盖率计划
| 覆盖率类型 | 目标 | 收敛动作 |
| --- | --- | --- |
| 行覆盖率（Line） | ≥95% | 未覆盖行逐条分析：补用例或证明冗余 |
| 分支覆盖率（Branch） | ≥90% | 同上 |
| 条件覆盖率（Condition） | ≥85% |  |
| 状态机/翻转（FSM/Toggle） | 状态 100%、关键总线翻转 |  |
| 功能覆盖率（Functional） | 验证点 100% | 定义 covergroup/coverpoint 与交叉 |
- 禁止“凑覆盖率”：无效应付性激励不允许合入

## 7. 通过/失败标准（Exit Criteria）
- 所有 P0 用例 PASS；无未关闭 critical/major 问题
- 所有断言 0 失败；功能覆盖率 100%；代码覆盖率达表中目标
- 与 Golden Model 的结果偏差在 LLD 规定的量化误差内
- 未覆盖项/遗留问题必须有书面豁免（理由、风险、批准人）

## 8. 缺陷管理
- 分级：critical（功能不可用/数据错误）/ major（边界场景错误）/ minor（日志、可读性）
- 每个缺陷：现象、最小复现（种子/激励）、定位模块、根因、修复、回归结果
- 缺陷记录位置：docs/05_bringup/05-03_调试记录.md（或 issue 系统）
