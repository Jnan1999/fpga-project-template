# 05-01 板级 Bring-up 计划（Board Bring-up Plan）

> 上板不是“走到哪算哪”，而是按顺序、可回退、每步有判据的验证。每一步通过才进入下一步；失败的定位路径事先想好。遵循“先静态、后动态；先接口、后链路；先单功能、后全功能”。

## 1. 前置条件（Gate）
- [ ] 系统级仿真通过、覆盖率达标（03-04）
- [ ] 时序收敛、资源达标（04-02）
- [ ] 可测性寄存器/错误码/DFT 接口就绪（寄存器规格 §2/§3）
- [ ] 命令表、测试码、测试脚本（host/scripts）就绪
- [ ] 仪器与电源就绪：示波器、逻辑分析仪、串口、网口、（信号源）

## 2. Bring-up 顺序（每步：目的/操作/通过判据/失败排查）
| 步骤 | 目的 | 操作 | 通过判据 | 失败排查路径 |
| --- | --- | --- | --- | --- |
| B0 上电静态 | 电源/时钟 | 测电源、晶振、MMCM lock | 电压正常、lock=1 | 电源/时钟引脚 |
| B1 下载与启动 | 基本链路 | 下载 bit/elf，读 VERSION | 版本正确、串口 banner | FSBL/引脚/启动模式 |
| B2 寄存器访问 | AXI-Lite | 遍历读写寄存器、复位值 | 与寄存器规格一致 | 地址/位宽/互联 |
| B3 ADC 测试码 | 采样接口 | SPI 配置，发 checker/PN/ramp | 码型 100% 正确、lock=1 | IDELAY/位序/约束 |
| B4 扫眼标定 | 相位裕量 | 全 tap 扫描，记录窗口 | 窗口中点、左右裕量达标 | 随路时序/信号质量 |
| B5 单帧采集 | 数据通路 | 命令 0x01 单帧 | 帧头帧尾/长度正确 | DMA/缓冲/帧打包 |
| B6 连续流 | 持续传输 | 命令 0x0F 连续，统计丢包 | 序号连续、丢包率达标 | 环形缓冲/流控/CPU |
| B7 数据正确性 | 全链路 | 采集数据与 Golden Model 比对 | 误差在指标内 | 定点/算法/位宽 |
| B8 性能压测 | 吞吐/延迟 | 满负载长测 | 达 PR 指标 | 带宽/中断/内存 |
| B9 异常与恢复 | 鲁棒性 | 断网/错误帧/复位/重连 | 报警码正确、可恢复 | 状态机/watchdog |
| B10 长稳 | 稳定性 | 连续运行 __ 小时 | 零丢数、无死锁 | 内存泄漏/温漂 |

## 3. 串口/报警规范（板级快速定位）
- 每条命令回显：命令字、写入参数、PL 应答
- 统一报警：[ERR][错误码][模块][简短描述]，错误码与寄存器规格一致
- 关键统计周期上报：in_cnt/out_cnt/drop_cnt/水位

## 4. 数据核对方法
- 板载原始数据（光谱）与结果数据分别上传、分别存档
- host/scripts 自动解析、Golden Model 计算、三路对比：上位机模型 / 板上传原始 / 板上解调结果
- 输出对比报告（逐点差异、统计、异常定位）

## 5. 回退与安全
- 每个稳定版本保留 BOOT.BIN 与 commit；新版本失败可回退
- 可能损伤硬件的步骤（时钟/电压）单独标注并在确认后执行

## 6. 风险与预案
| 风险 | 征兆 | 预案 |
| --- | --- | --- |
| 相位温漂 | 升温后误码 | 周期重标定/增大裕量 |
| 网口丢包 | 序号跳变 | 降速/加大缓冲/查流控 |
| DMA 卡死 | 无中断 | watchdog 复位 DMA |
