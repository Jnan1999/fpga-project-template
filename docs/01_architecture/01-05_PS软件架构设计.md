# 01-05 PS 软件架构设计（Embedded Software Architecture）

> 裸机/RTOS 侧软件的结构、状态机、数据通路与上位机协议实现。软件与硬件同样需要模块分层、接口定义和测试方案。

## 1. 软件分层
```
应用层    app/main.c：主状态机、命令调度、自检流程
服务层    udp_transmission / frame_protocol / data_path / watchdog
驱动层    drivers/xxx：寄存器封装、DMA 封装、SPI 配置、中断
板级层    BSP / lwIP / xparameters（工具生成，不手改）
```
- 规则：应用层不直接读写寄存器，一律通过驱动层；工具生成文件不手改

## 2. 主状态机
| 状态 | 进入条件 | 行为 | 退出条件 |
| --- | --- | --- | --- |
| INIT | 上电 | 初始化网口、SPI、ADC、DMA、读取版本 | 自检通过 |
| IDLE | 初始化完成 | 等待命令、心跳 | 收到开始命令 |
| STREAMING | 开始 | 配 DMA→启动 PL→接收中断→组帧→UDP 发送 | 停止/错误 |
| SELF_TEST | 自检命令 | 下发测试码、扫眼、校验 | 完成/失败 |
| FAULT | 任意错误 | 记录错误码、报警、安全停机 | 清错命令 |

## 3. 数据通路（PS 侧）
- 3.1 DMA → DDR 环形缓冲区：缓冲块数量、每块字节数、回卷、写指针/读指针管理
- 3.2 零拷贝：PBUF_REF 引用 DMA 缓冲，避免 memcpy；cache invalidate/flush 位置
- 3.3 在途帧数限制（MAX_FRAMES_IN_FLIGHT）、背压：网口慢时如何让 PL 停/降速
- 3.4 同步：DMA 完成中断 → 回调 → 入队 → 发送任务，中断只做最短处理
- 3.5 数据完整性：帧序号连续性检查、帧头帧尾校验、丢包统计、watchdog

## 4. 命令处理
- 命令分发表（命令字/参数校验/处理函数/响应）；非法命令统一错误应答
- 命令与 PL 寄存器映射：每条命令对应哪些寄存器写入、哪些状态回读
- 串口日志：统一前缀 [MODULE][LEVEL]，报警码与寄存器错误码一致

## 5. 性能与内存
- 中断负载评估、lwIP 内存池（MEM_SIZE/PBUF_POOL）配置依据、CPU 占用率
- 堆/栈大小、内存静态化（避免碎片化）、最坏执行时间分析

## 6. 软件测试
| 层级 | 内容 | 方法 |
| --- | --- | --- |
| 模块测试 | 帧解析/环形缓冲/命令表 | PC 上用 gcc 编译纯逻辑模块做单测 |
| 集成测试 | 驱动+寄存器（仿真器/板级） | 命令表逐条 |
| 压力测试 | 高吞吐/长时间/断连恢复 | 自动化脚本 |
| 数据正确性 | 板载结果 vs 上位机 Golden Model | host/scripts 比对 |

## 7. 构建与发布
- 工具链、BSP 配置项（lwIP 参数、xilffs 等）、链接脚本
- 产物：FSBL → bitstream → app.elf → BOOT.BIN 的打包步骤（脚本化）
- 版本号/构建信息注入（编译期宏、VERSION 寄存器可读）
