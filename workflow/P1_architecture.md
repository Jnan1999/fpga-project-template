# P1 系统架构（System Architecture）

> 阶段目标：把 SRS 落到具体的系统结构——模块划分、数据流/控制流、PS/PL 分工、时钟复位架构、寄存器映射。
> 出口后系统的"骨架"冻结，后续阶段只在骨架内工作。

## 1. 入口条件
- G1 通过：`project.yaml` 中 `P0.status: done`

## 2. Agent 输入（必读）
> 以下清单为**最低要求**（下界非上界）。

| 输入 | 路径 |
| --- | --- |
| 需求基线 | `docs/00_project/00-02_SRS`、`00-03_RTM`、已确认的 `00-00_需求确认清单.md` |
| 参考资料 | `docs/refs/`（datasheet 接口时序章节重点读） |
| 架构文档模板 | `docs/01_architecture/01-01 ~ 01-05` |
| 器件信息 | `project.yaml` 一区（part / board） |

## 3. Agent 任务
1. 生成 `01-01_系统架构设计_HLD.md`：
   - 模块划分表（模块/职责/接口/时钟域/关键参数）；模块粒度：单模块 RTL 工作量 ≤ 1~2 周为宜
   - PS/PL 职责划分表（高速时序/算法流水线 → PL；协议栈/业务逻辑 → PS）
   - 数据流（位宽、定点格式 Qm.n、各级吞吐、反压传播路径）与缓存策略（FIFO 深度依据 → DMA → DDR 环形缓冲）
   - 资源预算表（各模块 LUT/FF/BRAM/DSP 估算，总量 ≤ 80%）
2. 生成 `01-02_接口控制文档_ICD.md`：**接口优先复用成熟标准**（AXI-Stream 数据、AXI-Lite 寄存器、AXI-DMA 搬运），自定义协议必须给出理由
3. 生成 `01-03_寄存器映射规格.md`：基地址、寄存器总表、位域、错误码、访问规则
4. 生成 `01-04_时钟与复位架构.md`：时钟树、复位树、**CDC 逐条清单**（每条含同步方式与验证方法）
5. 生成 `01-05_PS软件架构设计.md`（裸机）：主状态机、命令调度、中断、环形缓冲/零拷贝、cache 一致性策略
6. **登记 `project.yaml`**：
   - `interfaces:` 登记全部模块间接口（name/from/to/protocol/width/clock/icd_section，`frozen: false`）
   - `modules:` 登记全部模块（status: design，rtl/tb/lld 路径按命名约定填）
   - `registers.base:` 填实际基地址

## 4. 验证命令
本阶段无代码命令。完工自查项：
- [ ] RTM 每条功能需求在 HLD 模块划分表中有承接模块（逐条对照）
- [ ] `project.yaml` interfaces 每条与 ICD 章节一一对应，且字段完整
- [ ] 每条跨时钟域路径在 01-04 CDC 清单中有行
- [ ] 寄存器映射与 ICD 的 AXI-Lite 章节一致（地址/宽度/错误行为）
- [ ] 资源预算总量 ≤ 80%，BRAM/DSP 不超器件总量

## 5. 出口标准（G2 architecture review）
- 用户评审 HLD/ICD/寄存器映射通过（重点：接口选型是否复用成熟标准、模块划分是否合理）
- 用户确认后更新 `project.yaml`：`P1.status: done`、`P2.status: in_progress`、`current_phase: P2`

## 6. 常见失败模式
| 失败模式 | 规避 |
| --- | --- |
| 自造接口协议而不复用 AXI 标准 | 默认 AXI-Stream/AXI-Lite；自定义须写明理由并经用户确认 |
| 寄存器映射与 ICD 不一致 | 两份文档同一次提交修改，互相引用章节号 |
| 时钟树缺 CDC 分析 | 每条跨域路径进 01-04 清单，注明同步方式；禁止多 bit 裸跨域 |
| 模块划分过细（几十个小模块）或过粗（一个模块做所有事） | 按"可独立验证、接口清晰"划分；拿不准列方案问用户 |
| 资源预算拍脑袋 | FIFO/缓冲按最坏反压计算 BRAM；乘加按并行度算 DSP |
