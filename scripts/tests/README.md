# scripts/tests/ —— 检查器自身的测试

> 评审#6b / ADR 0013：**检查器必须有自身测试，包含"故意引入错误必须失败"的反例（fail-closed）。**
> 否则检查器漏检会让错误设计通过门禁而不自知。

## 原则
- 每个检查器（check_ports.py、check_gate.py、new_module.py…）都要有对应测试
- 关键测试是**反例**：构造一个**已知错误**的输入，断言检查器**必须报错（退出码非 0）**。
  只测"正确输入通过"是不够的——那测不出漏检。
- 检查器修改后必须跑全套测试

## check_ports.py 至少覆盖
| 用例 | 类型 | 期望 |
| --- | --- | --- |
| 正常三件套（pulse_gen） | 正例 | 退出 0 |
| 分组声明差异（core `input a,b` vs dft `input a,c`） | 反例 | 退出 1，检出 b/c |
| 位宽表达式不同（`[CNT_W-1:0]` vs `[W-1:0]`） | 反例 | 退出 1 |
| 端口方向不同 | 反例 | 退出 1 |
| 无法识别的声明（宏/复杂类型） | 反例 | 报错退出（fail-closed，不放行） |
| dbg_ 前缀端口豁免 | 正例 | 退出 0 |

## 实现归属
测试代码与运行器在**第二批工具批**实现（本批只建目录与约定）。
运行方式建议：`uv run python -m pytest scripts/tests/`，纳入 CI。
