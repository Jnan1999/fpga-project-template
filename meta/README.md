# meta/ —— 模板与 Agent 的元开发记录

> 本目录**不参与 FPGA 项目开发工作流**，只记录「模板自身」和「驱动它的 agent」的演进。
> 与 `docs/`（项目设计文档）、`workflow/`（阶段操作规程）解耦。

## 目的
模板的每一次目录结构、工作流、agent 定义的调整，都**必须留下"为什么"**。
防止半年后没人记得当初为什么这么设计，也防止同类决策反复推翻。

## 两个子目录

### `decisions/` —— ADR（Architecture Decision Record）架构决策记录
一条重要决策一个文件，编号递增 `NNNN_标题.md`。每条记录：**日期/状态/背景/决策/理由/后果**。
状态取值：`已确认` / `提议` / `已废弃`（被新 ADR 取代时改状态并注明取代者）。
推翻旧决策不删文件，新建 ADR 引用它——保留决策演化轨迹。
**索引见 `decisions/README.md`**（含决策间关系图）。

### `devlog/` —— 开发流水日志
按日期记录每次实际改动（改了哪些文件 + 原因 + 关联的 ADR 编号）。
粒度比 ADR 细：ADR 记"决策"，devlog 记"动作"。

## 规则
- 修改 `workflow/`、`.claude/agents/`、目录骨架、`CLAUDE.md` 行为总纲 → **必须**配套一条 ADR 或 devlog
- 判断标准：改动会影响 Agent 行为或项目工作流 → 记 ADR；只是修补/同步 → 记 devlog
