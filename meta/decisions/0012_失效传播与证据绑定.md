# ADR 0012：失效传播矩阵 + 证据绑定 + 并行写入所有权

- 日期：2026-10-15
- 状态：已确认
- 来源：外部评审#3 + 并行/运行隔离扩展点

## 背景
现有工作流只有"推进规则"（Px.status: done），缺少"失效传播规则"：上游内容变了，哪些已完成结果必须作废？例如改 LLD 定点规则后原 Golden Model 还有效吗？改 XDC 后原时序批准还有效吗？此外多 Agent 并行触及共享文件有互相覆盖风险；并行回归/调试-发布构建可能覆盖同一工程。

## 决策（三部分）
**A. 失效传播矩阵**：定义"变更对象 → 至少需重新评估什么"。状态取值扩展为 pending/in_progress/gate_review/done/**stale**/**blocked**。
**B. 证据绑定**：每份验证证据记录 源码/配置摘要(git hash)+工具版本+测试集+种子+运行ID+结果+批准对象。**批准针对某次具体证据，不是笼统批准"P4 完成"**——证据失效则批准失效。
**C. 并行写入所有权**：子任务只改自己的设计/模型/验证目录；共享索引（project.yaml/filelist/测试矩阵/contracts）由协调者统一合并；验证证据由运行器产生；批准记录仅经用户授权后更新。运行产物按 目标板/debug|release/run_id 隔离。

## 理由
- 没有失效传播，"旧验证结果"会被误用于新设计（评审点名的核心风险）
- 证据绑定让"这次通过"可追溯、可失效，避免把旧报告当新结果

## 后果
- workflow/README 新增：失效传播矩阵、并行写入所有权、运行产物隔离三节
- project.yaml 状态取值扩展（stale/blocked）
- check_gate.py 后续需校验证据绑定的 git hash 与当前一致性
