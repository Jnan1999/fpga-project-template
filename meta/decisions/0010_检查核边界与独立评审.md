# ADR 0010：检查核的能力边界 + 独立评审（修正 ADR 0003 的 Lean 类比）

- 日期：2026-10-15
- 状态：已确认
- 来源：外部评审#1

## 背景
ADR 0003 把端口检查/回归/覆盖率/DRC 类比 Lean kernel。评审指出该类比有重要边界：这些检查只证明"已执行用例通过"，不能证明设计正确——仿真通过≠期望正确，覆盖率达标≠功能完备，GM 与 RTL 可能继承同一份 LLD 的错误，检查器自身也可能漏检。把它们统称"可信 kernel"存在"给错误设计盖章"的风险。

## 决策
信任模型改为三层并显式标注边界：**生成者 → 分层证据检查 → 独立评审与风险接受**。
- 每项检查"能证明什么/不能证明什么"在 workflow/README 用表格显式列出
- 派生四条硬规则：①测试期望/覆盖率排除/约束例外/检查器修改必须独立审核；②检查器须有自身测试（含"故意引入错误必须失败"反例）；③需求正确性与安全边界不因机器全绿免人审；④不同 Agent 角色是分工，不自动等于独立验证（独立性来自"依据不同来源推导"，不是换 agent 名）

## 理由
- 证据≠证明；明确边界才能知道何时必须靠人
- 独立性来自信息来源的独立（GM 从 LLD 独立推导、禁止反向翻译 RTL），这是真正能抓错的地方

## 后果
- workflow/README 信任模型节重写（三层 + 能/不能证明表 + 四条硬规则）
- 检查器自测要求落到 scripts/tests/（ADR 0013）
- 修订 ADR 0003 的"kernel"表述为"分层证据检查（非证明核）"
