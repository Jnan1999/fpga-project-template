# ADR 0016：三层职责 × 加载时机双轴架构 + 第五条铁律

- 日期：2026-10-16
- 状态：已确认

## 背景
用户提出 agent 分三层：Agent 设计层（skill 等功能设计）/ 项目工作流程层（workflow 分阶段）/ 工具操作层（vivado 脚本封装，换工具/版本可复用）。评审结论：职责划分正确且与仓库结构同构，但 Claude Code 的实际架构还有第二条正交轴——**加载时机**。用户随后确认参考 Claude Code 典型项目结构（CLAUDE.md / rules / commands / skills / agents / settings 两层）改造，且勘正：`.claude/rules/` 是**路径懒加载**机制（带 `paths` frontmatter 时只在编辑匹配文件时注入），不是"全局生效"。

## 决策
保留三层职责，按加载时机轴重新安放内容：

| 职责层 | 内容 | 安放位置（加载时机） |
| --- | --- | --- |
| Agent 设计层 | 铁律+行为总纲+路由表 | 根 `CLAUDE.md`（总是加载） |
| | 角色纪律 | `.claude/agents/`（子代理调用时） |
| | 人触发固定流程 | `.claude/commands/`（用户 `/project:*`） |
| | 稳定能力封装 | `.claude/skills/`（第三批起，模型自动调用） |
| 工作流程层 | 阶段 playbook P0~P6 | `workflow/`（CLAUDE.md 入口按 project.yaml 阶段路由——rules 的 paths 按文件路径匹配，做不了阶段路由） |
| 工具操作层 | 命名操作契约 + tcl/py 脚本 | `hw/scripts/ops.yaml` + 各入口脚本（执行时） |
| 横切数据面 | project.yaml / contracts / docs / meta | 不属于任一层，守单一事实来源（ADR 0011）+ 两区所有权（ADR 0006） |

编码规范从 agent 定义中剥离到 `.claude/rules/`（rtl-style / tb-style / tcl-ops），agent 定义只留角色纪律并以指针引用 rules。

新增**第五条铁律**：禁止绕过 ops.yaml 直接拼 vivado 命令（否则机读 SUMMARY、证据绑定、版本采集被旁路）。

## 理由
- rules 的 paths 按文件路径 glob 匹配，天然契合 hw/rtl、hw/verif、工具脚本三分布局——编码规范在编辑对应文件时才注入，是白捡的 context 节省
- commands（人按的按钮）与 skills（模型自己判断的能力）分工：gate/新模块流程固定且由人发起 → commands；sim-debug/timing-analysis 等模型该主动用的能力 → skills（稳定后）
- 铁律 5 是工具层解耦的 Enforcement：没有它，op 契约会被"顺手拼个命令"架空

## 后果
- CLAUDE.md 加铁律 5、路径速查补 rules/commands/ops.yaml 行、常用命令表改为斜杠命令 + op 名
- 三个 agent 定义瘦身（rtl-engineer 删除的编码规范由 rtl-style.md 承接）
- 修正 rtl-engineer 原"引用手册标注'待核实'"的降级表述 → 必须查证，无法查证时明确告知用户查哪本手册哪节
- skill 化规则：经历 2~3 个真实项目、契约零变更后才封装；skill 只是 op 之上的薄路由层
