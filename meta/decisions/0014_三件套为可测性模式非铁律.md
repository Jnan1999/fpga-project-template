# ADR 0014：三件套是可测性模式（默认），非所有模块的铁律

- 日期：2026-10-15
- 状态：已确认
- 来源：外部评审#7

## 背景
原 CLAUDE.md 把"每个模块三件套"列为铁律。评审指出三件套适合需观测/注入的业务模块，但不适合：common/ 的两级同步器/复位同步器、简单组合逻辑、官方原语/IP（对布局属性和 CDC 识别敏感）。同时"DFT 内部例化 core 所以功能不可能漂移"是过度断言——dft 本就故意在边界注入故障。

## 决策
- 三件套改为**默认的可测性模式**，不是无条件铁律。模块在 `project.yaml` 注册表用 `dft_mode` 声明：`three_piece`（业务模块默认）/ `ip`（官方 IP）/ `primitive`（官方原语）/ `none`（common 同步器、简单组合），并注明理由。
- DFT 保证改为精确表述：①注入关闭时 dft 与 core 满足规定等价关系；②注入开启时行为符合明确故障模型；③`ENABLE_DFT=0`（发布）时注入逻辑确实不存在/不可启用；④两种配置分别验证，不仅核对端口表。

## 理由
- 对官方 IP/原语强加三件套会破坏其布局/CDC 识别，得不偿失
- 精确的等价关系表述避免"例化 core 就万事大吉"的误解（注入本就是有意偏离）

## 后果
- CLAUDE.md 铁律 3 改写（含 dft_mode 例外说明）
- hw/rtl/README.md 的 1.1 节加精确保证说明
- project.yaml 模块注册表加 dft_mode 字段
