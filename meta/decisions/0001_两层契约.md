# ADR 0001：两层契约（硬契约围墙 + 软契约地板）

- 日期：2026-10-15
- 状态：已确认

## 背景
用户质疑：playbook 里写死每个阶段的"输入清单"，会不会反而限制大模型的自主检索能力？
担心 Agent 把清单当成"只许读这些"，丧失探索性。

## 决策
将契约显式分两层：
- **硬契约（围墙，不可逾越）**：出口机读判据（check_ports 退出码、WNS≥0、覆盖率数值）+ 禁止事项（frozen 接口、project.yaml 一区只读、core 禁调试代码）
- **软契约（地板，非天花板）**：playbook §2 的"Agent 输入"必读清单——是最低保障，不是上限

## 理由
- 必读清单防的是**漏读**（硬件项目最贵的失败模式：漏读 ICD → 接口漂移 → 几天仿真重跑），不是限制**多读**
- 探索型阶段（P0/P1）广搜优先；机械型任务（gate 检查、回归）确定性优先——契约保护后者，不束缚前者
- 类比飞行员 checklist：不限制判断天气，但保证不忘放起落架

## 后果
- CLAUDE.md 行为总纲新增：必读清单是下界不是上界；发现清单外相关资料必须主动阅读，并在汇报中注明额外读了什么
- 汇报注明额外阅读可让用户判断 Agent 依据是否可靠
- 七个 playbook §2 统一加"以下清单为最低要求"
