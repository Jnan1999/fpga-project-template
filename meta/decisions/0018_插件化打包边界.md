# ADR 0018：插件化打包边界（.claude 内容按可抽取为插件设计）

- 日期：2026-10-16
- 状态：已确认

## 背景
用户目标：当前开发的 agent 后期封装为 Claude Code 插件分发。因此 `.claude/` 下的内容设计以"可抽取为插件"为**目标**。

> ⚠️ 修正（评审 2026-10-16 #4 / ADR 0020）：**"抽取即插件、零重写"是目标，不是已成立的保证。** 仅用相对路径还不够——插件安装目录与项目根不同、命令名引入插件命名空间、内部硬编码 `/project:*` 会失效、agent 仍依赖项目 `.claude/rules/` 布局、初始化工具复制资源需保护用户已改文件。这些边界需用一个临时项目实际验证后才算成立。

## 决策
1. **插件候选集**：`.claude/agents/` + `.claude/commands/` + 未来 `.claude/skills/`。这三个目录的内容只允许引用项目内相对路径（workflow/、docs/、scripts/、hw/），禁止写入用户私有信息（本机绝对路径、个人授权）
2. **不进插件的**：
   - `settings.json` / `settings.local.json` / `settings.example.json` —— 权限随项目，插件不携带授权
   - 根 `CLAUDE.md` —— 项目骨架的入口文件，属于模板；插件可提供建议片段由项目 CLAUDE.md 引用
3. **rules/ 的处理**：路径模式（hw/rtl/** 等）绑定项目骨架；只要目标项目用同一骨架（模板生成的都满足），rules 可直接随插件分发。若未来骨架分叉，rules 留在模板侧
4. **插件配套但不进 .claude/ 的部分**：`scripts/`（检查器）、`workflow/`（playbook）、`docs/templates/`、`hw/scripts/ops.yaml` —— 插件包可携带这些文件，安装时落入项目对应位置；落地归第五批初始化工具
5. 版本归属：插件版本独立于 template_version / contract_version（ADR 0015 的演进分离原则延伸）

## 理由
- "可抽取"约束成本极低（保持相对路径引用 + 不写私有信息），但保留分发形态的最大灵活性
- 权限不入插件是 Claude Code 的安全模型使然（repo 可控来源不能授予权限），也是本仓库 settings.example.json 先例的自然延伸
- rules 绑定骨架而非绑定插件：骨架是模板的产物，rules 的 paths 假设与骨架同生命周期

## 两边界（插件化前必须用临时项目验证，ADR 0020）
- **插件携带**：能力（agents/commands/skills）+ 默认资源（rules 模板、scripts、workflow 模板、docs 模板）
- **项目持有**：需求、契约（contracts/）、状态（project.yaml）、生成物
- 验证项：命令参数与资源路径在项目/插件两种形态下都能正确解析；初始化工具复制资源时不覆盖用户已改文件

## 后果
- `.claude/README.md` 记录打包边界（本 ADR 摘要）
- 本批新增/改写的 agents/commands 均已遵守：仅项目内相对路径引用、无私有信息
- 后续每新增 .claude/ 内容时自查：能否原样进插件？（加入 .claude/README 备注）
