- 0000 是顶层架构（阶段模型），其余都建立在它之上
- 0003（信任模型）是方法论内核；**0010 修正其 Lean 类比**（证据≠证明）；0001 是其在"输入"维度的体现；0005 的 check_gate.py 是 kernel 的工具化
- 0007 修订 0002 的实施时机（MCP 层默认不启用）
- 0011/0012/0015 是评审驱动的架构补强：0011 定契约权威来源、0012 定失效传播与证据绑定、0015 定模板/项目边界
- 0013/0014 是评审驱动的精确化：0013 检查器 fail-closed、0014 三件套从铁律放宽为默认模式
- 0010~0015 均源自同一次外部架构评审（见 devlog 2026-10-15）
- 0016/0017/0018 是 Claude Code 原生化改造（见 devlog 2026-10-16）：0016 定双轴架构（职责×加载时机）、0017 定工具层 op 契约、0018 定插件化边界
- **0019 修订 0017**：用户 clarifying 后，工具操作从"op 白名单+铁律5 强制"改为"参考清单+机读契约"，并暂不引入 Vivado MCP；0016 引入的铁律 5 随 0019 撤销
- **0020 修正 0019、部分修订 0018**：外部评审驱动。核心原则从"SUMMARY 唯一硬要求"升级为"方法自由/证据可追溯/验收不可自改"；SUMMARY 降为反馈格式、证据 run_id 绑定、检查不隐含修复、先设计后实现、插件"零重写"降为目标。留两条待验证项（命令调用名、rules 触发时机）
