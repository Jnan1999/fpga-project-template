# ADR 0000：七阶段模型 + 接口冻结前置 + P3 并行

- 日期：2026-10-15
- 状态：已确认
- 注：编号 0000 因为它是全流程的顶层架构决策，早于具体技术决策（0001~0004）

## 背景
模板需要一个贯穿全流程的阶段模型。用户最初描述了自己的六阶段设想（需求→RTL→GoldenModel→验证→时序→上板），但明确"不一定是固定的六阶段，可自由决定，参考 Xilinx 官方手册与头部 IC 企业流程"。

## 决策
采用 **7 阶段模型**（V 模型 + UltraFast 方法论 + NASA/DO-254 压缩评审门禁）：
```
P0 需求捕获 ─G1→ P1 系统架构 ─G2→ P2 模块设计 ─接口冻结→ P3 并行实现 ─G3→ P4 功能验证 → P5 时序收敛 → P6 集成上板 ─G4→ Release
```
关键设计：
- **接口冻结前置到 P2 出口**：接口一旦冻结不再修改，写入 `project.yaml` interfaces 表（`frozen: true`）
- **P3 三线并行**：RTL 三件套 ∥ Golden Model ∥ 验证环境，接口冻结后三者互不依赖，可分派多 agent 同时推进——全流程最大时间压缩点
- **4 个正式 gate**（NASA FRR/FPDR/FCDR/TRR 压缩）：G1 spec review（P0 出口）、G2 architecture review（P1 出口）、G3 pre-commitment review（P3 出口）、G4 release review（P6 出口）
- **所有 gate 机器可检查**：每条 gate 对应可脚本提取的判据（WNS 数值、methodology warning 数、coverage 百分比、RTM 回填率）

## 理由
- 用户工作流明确"接口确定后尽量不再修改"，冻结前置才能让 P3 并行成立
- 传统串行（RTL→验证）在 Agent 驱动下不必要——三线输入都是已冻结的接口+LLD，天然可并行
- 机器可检查的 gate 是 Agent 自验证的前提（区别于人读报告的传统流程）
- 依据：UG949/UG1292（UltraFast 时序收敛）、NASA GSFC FPGA 评审流程、DO-254 双向追溯、UG994/XAPP1165（版本管理）

## 后果
- 产出 `workflow/` 七个 playbook，每个固定 6 节（入口条件/输入/任务/验证命令+机读判据/出口 gate/常见失败模式）
- `project.yaml` 二区包含 phases/modules/interfaces 状态机
- 相对用户最初六阶段：拆分出"接口冻结"为独立硬门禁、P3 并行化、Golden Model 独立成线
