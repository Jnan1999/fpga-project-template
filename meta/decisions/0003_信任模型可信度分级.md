# ADR 0003：信任模型——提议者/检查核/人审三层 + 按可信度分配任务

- 日期：2026-10-15
- 状态：已确认

## 背景
用户洞察：FPGA 项目是一个"几乎完美边界的闭包"——需求、接口、测试、验证规则完整细分，问题边界清晰，因此可以用 AI 的理解/迭代/审核来维护（类比 AI 在数学/Lean 的进展）。同时训练数据不对称：软件代码多而优质，IC/RTL 代码少而质量参差，所以不能完全信任 LLM 的 RTL 创造能力，但可以信任其阅读理解能力。

## 决策
将整个架构形式化为 Lean 式信任模型：
```
不可信的提议者（LLM 生成 RTL/文档/约束）
        ↓ 提议
可信的小型检查核 kernel（check_ports / 回归 / 覆盖率 / methodology DRC / 三路比对 / check_gate.py）
        ↓ 无法机器检查的部分
人审 gate（只剩这类才轮到用户）
```
**按可信度分配 Agent 工作类型：**

| 任务类型 | LLM 可信度 | 策略 |
| --- | --- | --- |
| 阅读/分析（时序报告、日志、datasheet、波形） | 强 | Agent 主战场（P4 归因、P5 分析、P6 比对） |
| SV/UVM 验证代码 | 较强（接近软件） | 激进放手，Agent 大量生成 |
| RTL 生成 | 弱 | **组合大于创造**：复用 common/ 组件 + 官方 IP + 三件套模板，新造逻辑最小化，每块新逻辑立即被验证闭包包住 |

## 理由
- Lean 的成功 = 小 proof kernel（绝对权威）+ 大 tactic generator（不可信但被 kernel 兜住）。映射到本架构：kernel = 机读判据，generator = LLM
- 训练数据不对称 → 不能让 RTL 创造"裸奔"，每块新逻辑必须立即被验证闭包捕获
- mathlib 类比：common/ 组件 + 官方 IP + 上过板的模块 = 可信积木库，每完成一个项目积木变多，下个项目 Agent 需"创造"的变少——这是模板长期复利的来源

## 后果
- workflow/README.md 新增"信任模型"一节（三层 + 可信度分级表）
- 架构优化总目标：最大化流经 kernel 的工作量占比，最小化"只能靠人判断"的残留
- 第二批 check_gate.py 的定位由此明确：把更多判断推进 kernel
