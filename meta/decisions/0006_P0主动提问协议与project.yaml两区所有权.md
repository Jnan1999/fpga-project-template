# ADR 0006：P0 主动提问协议 + project.yaml 两区所有权

- 日期：2026-10-15
- 状态：已确认

## 背景
用户补充 P0 阶段交互细节：打开空白项目后，用户先填项目基础信息（FPGA 型号、Vivado 版本等，**这类信息在开发流程中几乎不变**，不同于可能调整的需求）；然后提简单需求，Agent 应结合需求 + 用户上传的 datasheet + 目录结构，开启多轮对话生成待确认问题清单，**一定要让 Agent 主动提问，尽量把所有可能的需求在前期确定下来**。

## 决策（两部分）
**A. project.yaml 按所有权分两区**（同一文件，避免双文件同步）：
- 一区 `project:`：用户初始化时填写，整个开发流程几乎不变 → **Agent 只读，禁止修改**
- 二区（current_phase/phases/modules/interfaces/registers）：Agent 随流程维护，gate 相关更新需用户确认

**B. P0 主动提问协议**（写进 P0 playbook + CLAUDE.md 行为总纲 §2）：
1. 用户填一区 → 提需求 → 上传 datasheet 到 `docs/refs/`
2. Agent 综合三类输入，**禁止直接写 SRS**，先生成 `00-00_需求确认清单.md`（10 类问题 + datasheet 隐含需求，每问带【建议答案+依据】）
3. 多轮对话逐条确认，Agent 主动追问模糊项（如"采样率 100MSPS 是每通道还是合计"）
4. 清单全部 ✅ 后，Agent 才允许写 SRS/RTM

## 理由
- "基础信息几乎不变 vs 需求可能调整"是用户明确区分 → 用所有权分区而非两个文件承载
- Agent 易"假设需求直接产出"，硬件需求错位的返工代价极高（接口/架构全返工）→ 用流程强制"前期锁定"
- datasheet 隐含约束（电平标准/时序参数/初始化序列）是 Agent 易漏的，单列第 10 节并要求注明来源页码

## 后果
- 新增 `docs/00_project/00-00_需求确认清单.md` 模板、`docs/refs/` 目录
- CLAUDE.md 行为总纲 §1（一区只读）、§2（P0 主动提问）
- P0 出口 gate（G1）的前置条件 = 需求确认清单全勾选
