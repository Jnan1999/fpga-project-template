# ADR 0004：模板定位为基础骨架 + 占位符（供自研初始化工具生成空白项目）

- 日期：2026-10-15
- 状态：已确认

## 背景
用户明确：本模板是**基础目录骨架**，后续由用户自研的"初始化工具/skill"从它生成空白项目，便于与 Agent 交互。这决定了模板的设计约束。

## 决策
- 模板内项目特定信息一律用 `<...>` 占位符（当前仅 `<PROJECT_NAME>`、`<BOARD_NAME>` 两个），初始化工具负责替换
- 模板必须满足三点：(a) 变量可替换；(b) Agent 进入新项目能自主定位上下文（CLAUDE.md + project.yaml）；(c) 每阶段有明确的 Agent 输入/输出契约（workflow playbook）
- 初始化工具属"第五批"，由用户自研，模板侧只保证占位符完备、单一事实来源（project.yaml）可被工具读写

## 理由
- 模板会被复用生成多个项目，项目名/器件/开发板等不能在模板里写死
- 占位符收敛到 project.yaml 一区 → 初始化工具的替换面最小（grep 验证仅 2 个），降低工具开发难度
- Agent 自主定位上下文 → 新项目无需人工向 Agent 重新解释结构

## 后果
- `project.yaml` 一区用 `<PROJECT_NAME>`/`<BOARD_NAME>` 占位；其余（part/tool_version）给默认值 2021.1/xc7z020
- 模板自身不带具体项目内容，示例模块 pulse_gen 标注"新项目可删除"
- 验收标准含"模拟初始化工具替换占位符无遗漏（grep 检查）"
